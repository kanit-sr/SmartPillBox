# Test Plan

T01–T18 เป็น functional/integration/end-to-end test ของระบบ ส่วน automated checks บนคอมและตารางจับคู่ไฟล์โค้ดอยู่ใน [code-testing.md](code-testing.md) บันทึกผลใน [test-results.md](test-results.md)

ก่อนเริ่มแต่ละกรณี บันทึก Run ID, commit ของทั้งสองบอร์ด, การตั้งค่า, mode HARDWARE/MOCK และสถานะเริ่มต้นของ alarm/ตารางยา แยก log ต่อ gateway และต่อ boot/session สำหรับทดสอบ retry ต้องมี log ทั้งส่ง/รับและ ACK ไม่ใช้จำนวนข้อความบน cloud แทน packet loss ของ ESP-NOW

T11–T15 เพิ่มเงื่อนไขเสียและกู้คืนที่ต้องตรวจตามโจทย์ บางนโยบายยังไม่มีข้อกำหนดในระบบ ให้ตกลงและบันทึกก่อนรัน หากยังตัดสินผลไม่ได้ใช้ BLOCKED ไม่สมมติค่าหรือผลผ่านขึ้นเอง

| T10 | ที่เก็บยาร้อน/ชื้น | ใช้เกณฑ์อุณหภูมิ ความชื้น และระยะเวลาค้างที่ทีมกำหนด ทดสอบอุณหภูมิเกินและความชื้นเกินแยกกัน แล้วคงค่าผิดปกติต่อเนื่อง | ได้ storage_warn พร้อม temp, hum ตรงค่าจริง; เมื่อไม่มี alarm อื่น กล่องแสดงไฟเหลืองและสถานะ storage_warn; LINE แจ้งครั้งเดียวในช่วงผิดปกติต่อเนื่อง | NOT RUN |

| T12 | กล่องไฟดับแล้วกลับมา | บันทึก schedule, alarm และคิว จากนั้นตัดไฟกล่องและเปิดใหม่ ทดสอบแยกขณะ idle/alarm/มีคิว และเปิดใหม่ขณะยังไม่มีเน็ต | กล่อง reconnect และ sync เวลา/อ่าน schedule กลับได้เองเมื่อเครือข่ายพร้อม; บันทึก recovery time; ตรวจนโยบาย alarm, คิว และ event ID หลัง reboot ตามที่ตกลง ไม่สมมติว่าคิว RAM คงอยู่ข้ามไฟดับ | NOT RUN |

| T14 | Wi-Fi/AP หายและกลับมา | ปิด AP ทดสอบระหว่างกำไลส่งข้อมูล เปิดกลับ channel เดิม แล้วทดสอบเปลี่ยน channel ในรอบใหม่ เก็บ log scan/ACK/queue | กล่องและกำไลกลับมาสื่อสารได้เอง; event ที่ได้รับ ACK แล้วไม่กลายเป็นเหตุใหม่; คิวระบายและ dashboard กลับมาอัปเดต; บันทึกช่วงข้อมูลสูญหายและ recovery time | NOT RUN |
| T15 | ตารางยา / คำสั่งไม่ถูกต้อง | ใน test device ลอง 24:00, 08:60, string แทน array, JSON เสีย และ cmd ที่ไม่รู้จัก; ทดสอบตารางว่าง/ซ้ำและแก้ระหว่างเตือนหลังตกลงนโยบาย | ค่าผิดไม่ทำให้ crash หรือเขียนทับตารางดีโดยไม่แจ้ง; คำสั่งไม่รู้จักไม่เคลียร์ alarm; ค่าถูกอ่านกลับและใช้จริง; ต้องตรวจฝั่ง gateway ด้วยไม่ใช่เฉพาะ UI | NOT RUN |
| T16 | Alarm ซ้อนกับเตือนยา | ให้ถึงมื้อยาแล้วส่ง fall/SOS; ทดสอบเปิดฝาและครบ 30 นาทีคนละรอบ; กดปุ่มกล่องครั้งแรก/ครั้งที่สอง; ส่งเหตุใหม่ระหว่าง alarm | fall alarm มีลำดับสูงกว่า แต่เวลายาไม่รีเซ็ต; pill_taken/missed ยังเกิดตามเงื่อนไข; ปุ่มแรกเคลียร์ fall และปุ่มถัดไป mute ยา; เหตุใหม่ไม่รีเซ็ตเวลา alarm เดิม ตาม state diagram | NOT RUN |
| T17 | ขอบเวลาและ ACK/retry | ทดสอบปล่อยปุ่มก่อน/ที่ 3 วิและก่อน/ที่ 10 วิ, เปิดฝารอบขอบ 2 วิ, countdown รอบ 15 วิ; จำลอง ACK หายและส่ง packet seq ซ้ำ | ปุ่มค้างครบ 10 วิปิดเครื่องโดยไม่ยิง SOS ก่อน; SOS เกิดเมื่อปล่อยตั้งแต่ 3 ถึงก่อน 10 วิ; ฝาต้อง >2 วิ; ACK ของ seq/type ตรงกัน; รับซ้ำตอบ ACK แต่ไม่เริ่ม alarm ใหม่; บันทึกความคลาดเคลื่อนเวลาที่เครื่องมือวัดได้ | NOT RUN |
| T18 | Dashboard ↔ gateway และข้อมูลย้อนหลัง | ทำ D01–D06 ใน dashboard/README.md รวมเคลียร์ alarm, บันทึกตาราง, รีเฟรชหน้า, ดึง Feed และเทียบกับ log; ตรวจมือถือ | คำสั่งถึง gateway และผลย้อนกลับแสดงถูก; Feed อ่านย้อนหลังได้; missing/zero/stale แยกถูก; ประวัติ event และสถิติต้องตรงแหล่งเก็บจริง; เก็บ screenshot/command/event | NOT RUN |

## เงื่อนไขที่ต้องยืนยันก่อนตัดสินผล

- T10: threshold อุณหภูมิ/ความชื้น ระยะเวลาค้าง และเงื่อนไขแจ้งซ้ำ
- T11: วิธีรายงาน sensor failure และ stale ของแต่ละ field เพราะ schema ปัจจุบันไม่มี error field ครบทุก sensor
- T12: การกู้ alarm/คิวหลังไฟดับ, event ID ข้าม reboot, การทำงานก่อนมีเวลา NTP; การเก็บคิวข้าม reboot ยังไม่ใช่สิ่งที่ระบุใน schema
- T15: empty/duplicate schedule, จำนวนมื้อสูงสุด, การแก้ตารางขณะเตือน และการตอบกลับคำสั่งผิด
- T17: ให้ยึด [state-diagram.md](../../1-system-architect/docs/state-diagram.md) ที่ตัดสิน SOS ตอนปล่อยปุ่ม; กรณีการกดพร้อม timeout ให้ทีมกำหนดลำดับก่อนวัด

แผนวัดสมรรถนะอยู่ใน [metrics.md](metrics.md) และรันทดสอบต่อเนื่องใน [field-test.md](field-test.md) ไม่นับรัน 24 ชั่วโมงว่าแทนการทดสอบ T01–T18 ครบทุกกรณี
