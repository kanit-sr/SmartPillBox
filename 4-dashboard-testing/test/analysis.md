# วิเคราะห์ผลและเปรียบเทียบ

สถานะ: ยังไม่มีผลวัดจริง เอกสารนี้เป็นโครงสำหรับหัวข้อ Testing and Analysis ในรายงาน ไม่ใช่บทสรุปว่าระบบบรรลุเป้าหมายแล้ว

## 1. เทียบกับเป้าหมายของทีม

นำค่าจาก [metrics.md](metrics.md) และผล T01–T18 มาอธิบายว่าเหตุใดผ่านหรือไม่ผ่าน ใช้จำนวนตัวอย่างและเงื่อนไขเดียวกับหลักฐาน

| เป้าหมาย / Test ID | ผลวัด + n / ช่วง min–max | ผ่านเป้าหมาย? | สาเหตุที่มีหลักฐานรองรับ | แนวทางแก้ / สิ่งที่ต้องวัดเพิ่ม |
|---|---|---|---|---|
| รอกรอก | ยังไม่มีผล | ยังตัดสินไม่ได้ | — | — |

แยก “สังเกตจาก log” กับ “ข้อสันนิษฐาน” เช่น การส่งช้าเกิดพร้อม retry ยังไม่ยืนยันสาเหตุทั้งหมด หากแก้แล้วให้เทียบก่อน/หลังด้วยเงื่อนไขเดิมและเก็บผล FAIL เดิมไว้

## 2. เทียบระบบหรือผลิตภัณฑ์ใกล้เคียง

เลือกระบบอย่างน้อยหนึ่งรายการที่มีเอกสารอ้างอิงตรวจสอบได้ เช่น งานวิจัย/โครงงานเตือนยาหรือตรวจล้มที่ใช้รูปแบบการวัดใกล้กัน ระบุ URL, วันที่เข้าถึง, วิธีวัดของแหล่งนั้น และเงื่อนไขที่ต่างกัน ไม่ใช้ตัวเลขโฆษณาเป็นผลทดสอบภายใต้เงื่อนไขเดียวกับทีม

| ตัวชี้วัด | SmartPillBox (ผลจริง + Run ID) | ระบบเปรียบเทียบ / แหล่งอ้างอิง | เงื่อนไขที่เทียบได้/ไม่ได้ | ข้อสรุปที่ข้อมูลรองรับ |
|---|---|---|---|---|
| latency | ยังไม่วัด | รอเลือกและค้นแหล่งข้อมูล | จุดเริ่ม/ปลายทาง, countdown, เครือข่าย | ยังสรุปไม่ได้ |
| AI accuracy / recall | ยังไม่วัด | รอเลือกและค้นแหล่งข้อมูล | dataset, class balance, test split | ยังสรุปไม่ได้ |
| battery life / power | ยังไม่วัด | รอเลือกและค้นแหล่งข้อมูล | ความจุแบต, duty cycle, งานที่เปิด | ยังสรุปไม่ได้ |

ถ้าแหล่งเปรียบเทียบไม่รายงาน metric ให้ใส่ “ไม่รายงาน” ไม่ใส่ 0 และไม่สรุปว่าของทีมดีกว่า โจทย์ให้คะแนนสูงสุดในหัวข้อนี้เมื่อใช้ค่าที่วัดจริงเทียบทั้งเป้าหมายและระบบเดิม

## 3. ข้อจำกัดและสิ่งที่จะพัฒนาต่อ

- จำนวนและความหลากหลายของข้อมูลทดสอบ / ความต่างจากผู้ใช้เป้าหมาย: รอกรอก
- ความแม่นของเครื่องมือวัดและการ sync เวลา: รอกรอก
- เงื่อนไขที่ไม่ผ่านหรือไม่ได้ทดสอบ: รอกรอก
- ฟีเจอร์ที่ยังไม่มี implementation หรือหลักฐาน เช่น persistent event history: รอกรอก
- สิ่งที่จะปรับปรุง พร้อม metric ที่จะใช้พิสูจน์: รอกรอก
