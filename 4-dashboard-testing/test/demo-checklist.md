# แผนเดโมและหลักฐานสำรอง

สถานะ: ยังไม่ซ้อมจริง ใช้ร่วมกับทีมภายในเวลานำเสนอรวม live demo 10 นาทีตามโจทย์ หน้า 5 ผู้รับผิดชอบแต่ละช่วงต้องอธิบายโค้ดและข้อมูลของตนได้

## ก่อนเดโม

- [ ] firmware และ dashboard revision ตรงกับผลทดสอบที่นำเสนอ
- [ ] hotspot ส่วนตัวพร้อม, บอร์ดต่อได้, ยืนยัน channel และ timezone
- [ ] dashboard, Feed และหน้ารับ LINE เปิดพร้อม; หน้าจอไม่มี token/secret
- [ ] คิว/alarm เริ่มต้นและ schedule ถูกบันทึกไว้ก่อนเปลี่ยนค่า
- [ ] ชุดจำลองเหตุพร้อม ไม่ใช้ผู้ทดลองล้มจริง
- [ ] มีคลิปสำรองที่มาจากการทำงานจริง พร้อม Run ID/วันที่ ไม่ใช้ mock เป็นหลักฐานการทำงานครบระบบ
- [ ] ทีมยืนยัน M1/M2 และข้อกำหนด M7 ตาม [requirement-coverage.md](requirement-coverage.md)

## ตัวอย่างลำดับภายใน 10 นาที

| เวลา | สิ่งที่แสดง | หลักฐาน/ผู้รับผิดชอบ |
|---|---|---|
| 0:00–1:00 | ปัญหา ผู้ใช้ และภาพ sensor → gateway → cloud → dashboard | Architect / ภาพระบบ |
| 1:00–2:00 | ข้อมูล sensor จริงบน dashboard และเปิดกราฟย้อนหลัง | Dashboard / D01, D05, Feed |
| 2:00–4:00 | กระตุ้น fall หรือ SOS → alarm + LINE → เคลียร์จาก dashboard | Sensor + gateway + dashboard / T01 หรือ T03 |
| 4:00–6:00 | ตั้งมื้อทดสอบใกล้เวลาปัจจุบัน → เตือน → เปิดฝาตามเงื่อนไข | Gateway / T04; แสดง schedule ที่อ่านกลับ |
| 6:00–7:30 | ตัดเครือข่ายที่เตรียมไว้ → event เข้าคิว → คืนเน็ต | Gateway / T06; ตอน offline ดูคิวจาก serial |
| 7:30–9:00 | ผลวัดอย่างน้อย 3 ประเภท ความแปรผัน และผลต่อเนื่อง 24 ชม. ถ้ามี | Test lead / metrics และ raw evidence |
| 9:00–10:00 | วิเคราะห์ผล ข้อจำกัด และหน้าที่ของสมาชิก | ทุกคน / analysis |

กรณี 30 นาที, แบตเตอรี่ และ 24 ชั่วโมงใช้หลักฐานรอบทดสอบจริง ไม่ต้องรอครบใน live demo หากใช้ test build เร่งเวลาให้บอกค่าที่เปลี่ยนบนสไลด์และใน Run ID แล้วคืนค่าหลังซ้อม
